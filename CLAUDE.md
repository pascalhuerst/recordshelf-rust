# recordshelf-rust

Desktop GUI (egui/eframe 0.27) for cataloguing vinyl via the Discogs API. A USB barcode scanner (read as a Linux evdev keyboard device) feeds codes; the search view finds releases and adds them to a Discogs collection folder. Linux only (evdev). Edition 2024.

## Commands
- Run (starts fullscreen; `--windowed` opts out, F11 toggles): `cargo run -- [--config PATH] [--token T] [--username U] [--device-name N] [--device PATH] [--currency C] [--user-agent UA]`
- Check: `cargo clippy --all-targets`, `cargo fmt`, `cargo test`
- Reading `/dev/input/event*` needs permissions (input group or root).

## Configuration
- Settings file: `~/.config/recordshelf/config.toml` (`config.rs`, written with mode 0600). Editable in the in-app Settings window; saving applies immediately (restarts scanner, reconfigures worker).
- CLI flags override the file for one run; token also via `DISCOGS_TOKEN`. Never hardcode credentials.
- UI zoom (egui's built-in Ctrl +/-/0) is saved as `zoom_factor` on every change via `Settings::save_zoom`, which only rewrites that key on disk (CLI overrides are not persisted).
- Scanners are found by device **name** (substring, case-insensitive); `device_name` may list several names separated by `;` and every device matching any of them gets its own reader thread (several receivers at once; `pick_devices`, `spawn_readers`, `scanner_active`; plugged-in ones are picked up by the 3 s retry). `device_path` is only a fallback. The settings "Pick..." list toggles a name in/out of the list and shows all devices that report keys (keyboard-like ones first, then "Other input devices").

## Architecture (src/)
- `main.rs` – clap `Args`, loads `Settings`, applies overrides, starts eframe.
- `config.rs` – `Settings` (serde/TOML) load/save.
- `barcode_reader.rs` – evdev: `list_devices`, `pick_device`, scanner thread (non-blocking, stoppable via flag). Only emits `ScanEvent::{Info, Code}`.
- `worker.rs` – single background thread owning the Discogs client. UI sends `Request`s, polls `Response`s (one response per request, FIFO; `Configure` has none). `pending()` drives the status-bar spinner. `ScanCode::classify`: 12–14 digits = UPC/EAN barcode (searched via `barcode=` param), shorter numbers = release id. A scan fills the results list (all pressings for a barcode, one row for a release id) and loads the first.
- `discogs.rs` – blocking `reqwest` client + serde models. Search items use lenient deserializers (Discogs returns mixed types). Collection instances come from `GET /users/{u}/collection/releases/{id}` (`releases[]` with `instance_id`, `folder_id`).
- Cover pictures: scans and searches share one results list; rows show `thumb`, details show the release `images` primary cover. Fetched lazily (only visible rows) by a separate image thread in `worker.rs` (not counted in `pending()`), only from discogs.com hosts, cached by URL in `ui.rs`, drawn via egui_extras image loaders.
- `ui.rs` – `RecordShelfApp`: single main view (search fields, results list, release details; keys: Up/Down browse, `A` add to the current folder, `R` remove, `P` print label (owned releases; the label as it would print is shown permanently at the right of the record info, `ui/label_preview.rs`: real size via `preview_ppi` points per inch (default 96) minus the Ctrl+/- zoom, only for a shown release with a copy, left out when the window is too narrow; the details are split in two halves by a vertical line (`split_pane`), the right one holds the padded picture and the toggles for style tags (off/outlined/filled) code (barcode/QR) and checkboxes for the parts of the label (header, artist, title, tracks, code: `label_hidden` setting, `LabelParts` in `label.rs`, also in `PrintJob.parts`), which change and persist `label_tags`/`label_code` via `apply_label_action`), `S` sync to library, `U` auto sync, F1/F2 switch tabs, `M` move to another folder (asks which copies if there are several), `O` open in browser, `F` change folder, `Q` quit, Enter retries a failed load, Esc new search; the same commands are buttons showing their keys; logic in `controls.rs`), folder picker window, Settings window, bottom status bar. Never do network I/O on the UI thread; send a `Request`.

- `shops.rs`, `decks.rs`, `hhv.rs`, `shop_bridge.rs` – lookups of decks.de / hhv.de label codes via a browser userscript (`--shop-bridge`); `ShopEntry` → Discogs search plan (barcode, catno+label, catno, artist+title; results narrowed to those naming the artist, `prefer_artist`). deejay.de (QR code with the article URL) needs no browser: `Route::Fetch`, the worker fetches the page directly (`deejay.rs`, plain client without Discogs credentials). With `--shop-bridge` the app opens the decks.de and hhv.de pages in the browser after 3 s unless their tabs are already connected (`open_shop_tabs`, `Shop::tab_url`, settings `shop_open_tabs`/`shop_browser`, `--no-shop-tabs`; the opener is injectable for tests). The scanner thread tracks Shift (`KeyDecoder`, US layout) so `:` and `_` of URLs arrive. A scanner that is not found is explained in the status bar (with the connected input devices) and looked for every 3 s (`retry_scanner`, also after it was unplugged: the thread ends with `ScanEvent::Stopped`), so plugging it in is enough. 6-7 digit numbers are treated as hhv article numbers while the bridge runs (also with leading zeros or a variant suffix such as `525768V1`: `hhv::article_number`, `shops::normalize_scan`; the shop's sku may carry the variant (`853005v1`) while the lookup asks for the number, `hhv::find_entry` compares article numbers). See `shops.md`. Personal tool, never to be published.

- `db/` – PostgreSQL for our own catalogue: numbered migrations, `db/db.sh bootstrap|migrate|status` (psql based, checksummed, transactional; bootstrap creates role + database), tests in `db/test.sh` (throwaway cluster). See `db/README.md` for the schema, conventions and how Discogs data maps onto it. `bootstrap` writes `database_url` into the settings file (`Settings.database_url`; unknown keys in the file are preserved on save via a flattened `extra` map); `drop` removes it again. Server: lightdesk.local (PostgreSQL 17).
- Two tabs (`Tab`): "Add records" (everything described above, `ui_main`) and "Search Collection" (`ui/collection_tab.rs` + pure state in `collection.rs`): all records of our database loaded at once (`Library::list`), client side search (all words, case/accent-insensitive via `catalogue::fold`), virtualised list with lazily loaded thumbnails (`db:thumb:ID` keys in `images`), details from the database (`StoredRelease`), `P` prints the label from stored data, `O` opens Discogs, `E` edits our own notes (`releases.my_notes`, migration 0002; searchable, never overwritten by sync), `D` deletes from the library only after a confirmation (Discogs untouched; auto sync may re-add it). Keys: Up/Down always move through the list (also while the search field has the focus, which it has when the tab opens); Esc clears the search; the letter commands (P O D E Q) only work when the field is not focused (Esc again leaves it, `/` goes back). The values in the details (artists, label, catalog number, year, country, format parts, genres, styles, credit names) are links that put the value into the search (`LinkSink`, `Collection::search_for`); the search understands `"quoted phrases"` (`search_terms`, `quote_for_search`), and credit names, my notes and format are part of the searched text. A scan on this tab only looks at our database (release id -> `Details{for_scan}` -> list shows just that record until Esc; barcodes/shop codes -> message), never Discogs. The list is reloaded after a sync (`collection_changed`).
- **Stacks** (migration 0003, `library/stacks.rs`, `ui/stacks_tab.rs`, F3 tab "Stacks"): records are labelled one after another and put back into a box in that order; a stack (`stacks`, `stack_records`) is a named, ordered list of records (positions 1..n, renumbered when a record is taken out or moved; unique per stack, but a record may be on several stacks; one stack is `active`). Later the order is used to fill the shelf ("7th record from stack ABC"), nothing of that exists yet. Printing a label (any tab) adds the record to the active stack when `stack_auto_add` is on (default, key `J` toggles, persisted); with it off `K` puts the shown record on the stack by hand (Add tab and Search Collection). One worker request does everything (`LibraryRequest::Stacks{op: StackOp, show}` -> `LibraryResponse::Stacks(StackState{stacks, shown, note})`: the full state again after each change, `note` is the status message). The tab: stack list at the left (`●` = active, N new, A make active, Rename, Delete with confirmation), records of the shown stack at the right (Up/Down select, Alt+Up/Down or number field move, R/Delete take out, Enter shows in Search Collection, a scanned sticker selects the record). Status bar shows the active stack. Records not in the library cannot be stacked.
- `catalogue.rs` (pure: Discogs `Release` -> `CatalogueRelease`: partial dates with precision, formats split into size/rpm/channels/weight, tracks, credits), `library.rs` (postgres crate: connect, embedded migrations with checksums compatible with db.sh, `save_release`, `delete_release`, `status`, `save_cover` + 150 px thumbnail; test helper `testing::server()` starts a throwaway PostgreSQL), library thread in `worker.rs` (`LibraryRequest/Response`, own thread; Configure is not counted in `pending()`). UI: `S` sync selected (forced), `U` auto sync on/off (`library_auto_sync`, persisted), `controls::decide_sync`, `LibraryLink` state + status bar indicator, `library_line` in the details. Sync rule: owned copies on Discogs -> store with that copy count; none -> delete. **New migration files must also be added to `MIGRATIONS` in `library.rs`.**

- `label.rs` – sleeve sticker (52x39 mm, test labels 51x38) drawn into a 1-bit bitmap at 203 dpi: size, label / catalog number, artist, title, tracks, plus the bare Discogs release id as QR (version 1, 4 dots per module) or Code 128 (set C). Fonts: DejaVu Sans Condensed in `assets/fonts`. `--label-preview DIR [--label-release ID]` writes PNG previews (3x). Tests decode the rendered codes with rxing. 
- `printer.rs` – Zebra ZD411 (203 dpi, thermal transfer) over raw TCP 9100: `~HS` status check before printing, `getvar` for settings, label bitmap sent as a ZPL `^GFA` graphic. The stock is centred in the 448 dot print area (`centred_x`) and starts `label_top_mm` (1.5) below the origin (measured with `--print-calibration`). Per label `^MD` (darkness, relative, `printer_darkness`, default +9) does not persist; **`^PR` (speed, `printer_speed_ips`, 0 = leave alone) DOES persist in the printer** (check `media.speed`; the printer's own was 6.0). Styles (not genres) can be drawn as tags between title and tracks (`label_tags` setting: off/outline/filled, default off; `TagStyle`, `PrintJob.tag_style`; `--print-tags-test` prints an example of each). Barcode default: Code 128, 3 mm high, 2 dot modules (tests read fine down to 2 mm). Test commands: `--print-calibration`, `--print-barcode-test`, `--print-darkness-test`, `--print-speed-test`. `P` prints the sticker for the selected release (only offered for owned releases; job built from the settings: `printer_host`, `printer_port`, `label_width_mm`/`label_height_mm` (default 51x38 test labels; set 52x39 for the real ones), `label_code`, `printer_darkness`, `printer_speed_ips` (default 3), `label_top_mm`) on the worker thread. All settings are editable in the Settings window (`show_settings`; values go through `Settings::normalized` on save; zoom and target folder change live via Ctrl +/- and F and are not part of the draft). Saving only clears fetched data / restarts the scanner when the Discogs or scanner settings changed.

## Conventions
- All Discogs searches are restricted to `format=Vinyl` (only vinyl is of interest); this is applied in `SearchQuery::params`.
- Errors: `anyhow` with `.context(...)`; worker turns them into `String`s for the UI; the UI shows them as a `Notice` in the status bar.
- Browsing results shows details without Enter: the first `PREFETCH_LIMIT` (5) results are prefetched (release + collection status), later ones load when the selection rests for 250 ms. Releases are cached in `releases`/`requested`; Enter only retries a release whose load failed (`failed`). Keep this in mind for the 60 req/min Discogs limit.
- Add/remove are optimistic (`PENDING_INSTANCE` placeholder, instance removed locally) and always followed by `resync_collection`. Adding a release that is already owned, and every removal, asks for confirmation (Enter/Y yes, Esc/N no). The target folder (never "All", id 0) is stored as `folder_id` in the settings file.
- Owned releases are flagged (ownership cache `HashMap<release_id, Vec<CollectionInstance>>`); adding a duplicate copy is always allowed.
- Tests live in `#[cfg(test)]` modules next to the code; Discogs HTTP is tested against a local one-shot `TcpListener` server (`DiscogsClient.base` is overridable in-crate).
- Keep clippy and fmt clean; commit only when asked.

## Known gaps
- Settings saved from the window also persist any CLI/env overrides active in that run.
- Scanner reports letters upper case regardless of Shift.
- No automatic scanner reconnect if the device is unplugged.
- The worker is a single thread, so a slow request delays the ones queued behind it.
- UI code (`ui.rs`) has only helper-level tests; no egui interaction tests.
- `/home/paso/development/recordshelf` (parent) is not a git repo; this directory is.
